## Project
"Are You Human? (Probably)" - a pixel-art CAPTCHA parody game.
Core idea: Bots take the perfect path. Humans get distracted.
Problem statement: Reimagine CAPTCHA.

## Tools
- **Google Antigravity** - main build tool (wrote index.html, tested it in headless Chrome, fixed bugs)
- **Claude** - planning, prompt writing, debugging help and step-by-step guidance
- **Suno** - background music (EDIT: keep only if you really used it, otherwise delete this line)
- **Web Audio API (generated by AI)** - 8-bit sound effects: move, wall bump, snack, pass, fail

## Key prompts
1. "Build a browser game as a single index.html (vanilla JS + canvas). Theme: pixel-art CAPTCHA parody 'Are You Human? (Probably)'. Cream graph-paper background, navy and gold. Snack Maze: random 10x10 maze (recursive backtracker), 3 snacks placed off the shortest path, fail if the player reaches the exit with 0 snacks."
   -> Result: playable core loop, start screen, round modal, results screen, restart without reload.
2. "Change the game from 5 rounds to 3 rounds. Every challenge has a 30 second timer that turns red in the last 5 seconds. Timeout = BOT DETECTED. 2 or 3 rounds passed = HUMAN VERIFIED, 0 or 1 = BOT CONFIRMED."
   -> Result: final verdict screen and a clear pass/fail rule.
3. "Make the Snack Maze easier to finish within 30 seconds: smaller maze, snacks placed near the shortest path, keep the 30s limit." (EDIT: say if you used this or the 45s version)
   -> Result: fairer difficulty for new players.
4. "Add looping 8-bit background music using the Web Audio API, start on the Start button, and make the SFX toggle mute it." (EDIT: or the Suno file version)
   -> Result: atmosphere and a mute control.
5. "Commit and push this to GitHub with a clear message" - used after each working version to build the commit history.

## How the AI helped in the game design
- The AI generated the maze with a recursive backtracker, so every maze is solvable.
- It used BFS to find the shortest path, then placed snacks off that path. That is how the "too efficient = bot" rule works.
- The AI added an auto-play test mode (a "human" player that grabs snacks vs. a "bot" player that takes the shortest path) to check both outcomes.
- The AI took screenshots of the start, game, pass, fail and final screens in headless Chrome to check the visuals.

## When AI got it wrong
- **Agent stopped at planning:** after our first prompt the agent only showed planning notes and we could not see index.html. We asked it to write the file, and found it had saved it in a OneDrive Desktop folder, not where we expected.
- **30 second timer was too hard:** snacks were placed randomly anywhere off the path, so some were too far to reach in time. We changed the maze size and snack placement. (EDIT: describe what you actually changed)
- **Only one challenge type:** the first build only had the Snack Maze. We covered the "random generator" requirement because every round generates a brand new random maze. (EDIT: add a line if you added the circle or checkbox challenge)

## What we learned
- Small prompts with one change each work better than one giant prompt.
- Commit after every working version, so you can go back if AI breaks something.
- Always test the AI's output in the browser, because the AI's own description is not proof.
